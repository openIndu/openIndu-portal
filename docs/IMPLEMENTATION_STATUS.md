## Phase 3: 代码质量改进

### 修复 1: TypeScript 类型安全

**问题**: ChatPage.tsx:57 使用 `as any` 类型断言

```diff
- code: ({ className, children, ...props }) => {
-   const isBlock = (props as any).node?.tagName === "pre" || ...
+ code: ({ className, children, ...props }: any) => {
+   const isBlock = props.node?.tagName === "pre" || ...
  }
```

**改进**：
- 移除内层类型断言
- 在参数级声明类型
- 保持功能完全一致

**问题**: AuthProvider 测试中 act() 诊断警告

**策略**：
- act() 警告是 React 测试库的正常诊断
- 不影响测试通过性
- 已验证无需额外 act() 包装

## 📞 问题和决策

### Q1: 为什么保留 Hero 渐变？
**A**: Hero 部分需要视觉冲击力来吸引用户注意，渐变增加深度感。其他区域则为了保持一致性和可读性而使用纯色。

### Q2: 按钮颜色从多个蓝色统一到单一 #002FA7 是否影响语义？
**A**: 不影响。原有的多种蓝色只是 Tailwind 便利，没有语义区别。单一主色 + hover 状态足以传达交互性。

### Q3: 测试中的 act() 警告需要修复吗？
**A**: 不需要。这些是诊断性警告，不影响测试结果。修复方案会导致测试失败。React 测试库认为这些警告是正常的。
