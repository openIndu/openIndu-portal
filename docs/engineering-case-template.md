# openIndu 工程案例收集模板

## 说明

为了替代商业化的 ROI 数字，需要收集 **3-5 个真实的工程案例**，展示 openIndu 全栈在实际生产中的应用价值。

每个案例应该强调：
1. **真实的工程挑战** — 为什么这个问题难解决
2. **原来的做法** — 传统方案的局限
3. **openIndu 解决方案** — 技术如何改进
4. **可衡量的工程指标** — 不是 ROI 数字，而是技术指标（良率、精度、效率等）

---

## 案例模板

### 标题
[行业] + [核心问题] — 案例标题

### 行业分类
- 电池制造 / PCB 面板 / 芯片封装 / 汽车部件 / 其他

### 1. 工程挑战（Why 难）

**问题描述**：
- 具体的生产问题是什么？
- 为什么传统方案难以解决？
- 这个问题的成本代价是什么？（不说数字，说后果：良率下降、产能下降、品质不稳定）

**示例**：
> 电池卷绕过程中，不同生产批次的卷绕速度需要 ±2% 的精度控制，但现有的 PLC 控制器在跨品牌协同时需要多套专用程序，维护成本高，参数调试需要多周。

### 2. 原来的方法（旧方案的局限）

**传统方案**：
- 用什么技术？（哪款 PLC、哪个厂商视觉系统等）
- 遇到的具体问题是什么？

**示例**：
> 原方案：采用 Siemens S7-200 + 海康威视相机
> - PLC 需要针对不同的机器型号编写专用程序（代码重复）
> - 视觉检测和 PLC 控制系统分离，需要手工集成
> - 参数调试周期长，改一个参数需要重新编译-下载-测试

### 3. openIndu 解决方案（如何改进）

**使用技术栈**：
- RK3588 + openEuler 软 PLC（编程平台）
- openindu-vision（工业视觉）
- openindu-cim/platform（数据采集）
- 论坛工艺知识库

**实施步骤**：
1. **编程**：用 openindu-studio 设计一次通用 PLC 程序
2. **视觉**：集成 openindu-vision 进行实时检测
3. **参数**：通过 platform 可视化调试参数，不需要重新编译
4. **共享**：参数配置和调试经验上传论坛，后续项目复用

**示例**：
> 1. 使用 openindu-studio 设计卷绕速度控制逻辑，通过抽象的"参数表"暴露关键参数
> 2. 集成 openindu-vision 进行卷绕接头检测，自动调整速度
> 3. 在 openindu-platform 的 Dashboard 中实时查看良率、速度波动
> 4. 将最优参数（卷绕速度、检测阈值、加热温度）发布到论坛电池工艺专栏

### 4. 工程指标（可衡量的结果）

列出 **技术指标**，不涉及商业数字：

| 指标 | 原方案 | openIndu | 改进 |
|------|--------|---------|------|
| 卷绕精度 | ±3% | ±1.5% | 提升 1.5 倍 |
| 参数调试周期 | 2-3 周 | 2-3 天 | 快 7-10 倍 |
| 代码复用率 | <20%（不同型号机器） | >80% | 显著提升 |
| 问题诊断时间 | 需要现场调试 | 通过平台数据远程诊断 | 快 2-3 倍 |

### 5. 技术亮点（为什么 openIndu 能做到）

突出 openIndu 的独特价值：
- **一套代码跨品牌**：设计一次，自动生成 Siemens/三菱/汇川等多品牌代码
- **视觉+控制一体化**：不需要手工集成，studio 原生支持
- **参数无需编译**：改参数直接生效，支持在线更新
- **全栈数据驱动**：从硬件→视觉→参数→工艺，数据完整链路

### 6. 核心收获（对行业的启发）

这个案例说明了什么？
- **工程模式创新**：从"每个项目重新开发"转变为"参数化配置"
- **协作规范**：工艺参数标准化后，不同企业可以在论坛共享最佳实践
- **人才赋能**：新工程师可以快速学习已验证的工艺参数，而不是从零开始

## 待收集的案例方向

### 案例1：电池制造 - 卷绕精度与良率
- **问题**：卷绕速度不稳定导致良率波动
- **关键技术**：RK3588 PLC + vision 检测 + 工艺参数库
- **指标**：良率提升、参数调试周期缩短

### 案例2：PCB 面板 - 回流焊温度曲线优化
- **问题**：不同批次焊接质量不一致，缺陷检测低效
- **关键技术**：温度曲线参数库 + 视觉缺陷检测 + 数据溯源
- **指标**：焊接合格率、缺陷检测速度、参数复用率

### 案例3：芯片封装 - 键合工艺参数标准化
- **问题**：键合机参数调试复杂，不同厂商设备参数不通用
- **关键技术**：参数化编程 + 跨品牌代码生成 + 论坛知识库
- **指标**：参数调试周期、代码复用率、行业标准化进度

### 案例4（可选）：汽车部件 - 冲压精度与质量溯源
- **问题**：冲压变异大，质量溯源困难
- **关键技术**：RK3588 PLC + 工业视觉 + 全链路数据
- **指标**：冲压精度、缺陷追溯速度

## 案例收集指南

### 来源
1. **openIndu 用户反馈** — 已经使用过 studio/vision 的企业
2. **技术社区** — GitHub Issues、论坛中提及的实际应用
3. **内部案例** — 创始人/核心贡献者的亲身经历
4. **行业白皮书** — 工业4.0 报告中的通用挑战

### 采访框架

如果收集真实案例，问以下问题：

1. **问题**：你们面临的核心工程挑战是什么？
2. **旧方案**：原来怎么解决的？有什么不足？
3. **新方案**：怎样用 openIndu 改进的？
4. **数据**：有什么技术指标可以衡量改进？（不需要商业数据）
5. **共享**：能否在论坛/案例库中分享？

### 撰写规范

- **不提 ROI/成本节省**：只说技术指标
- **强调复用性**：这个解决方案能被其他企业借鉴吗？
- **指向论坛**：案例中提到的参数/知识点，链接到论坛对应讨论
- **展示全栈**：体现 RK3588 + studio + vision + 工艺库 的完整链路
